# Руководство по исправлению плагина Snapmaker для Cura 5.x

Этот документ описывает процесс диагностики и исправления проблем с генерацией превью (thumbnail) в плагине Snapmaker для слайсера Cura версий 5.x (включая 5.11).

## 1. Проблема совместимости API (`def write`)

### Симптомы
Cura выдает ошибку при попытке сохранить G-код или плагин просто не срабатывает.

### Причина
В новых версиях Cura изменилась сигнатура метода `write` базового класса `MeshWriter`. Теперь он принимает дополнительные аргументы `mime_type` и `**kwargs`. Если их не указать, Python выдаст ошибку несовпадения аргументов.

### Решение
Мы обновили определение функции `write` в файле `SnapmakerGCodeWriter.py`.

**Было:**
```python
def write(self, stream, node, mode=FileWriter.OutputMode.BinaryMode) -> None:
```

**Стало:**
```python
def write(self, stream, node, mode=FileWriter.OutputMode.BinaryMode, mime_type=None, **kwargs) -> bool:
```
*   `mime_type=None`: Добавлен аргумент для совместимости.
*   `**kwargs`: "Пылесос" для любых других новых аргументов, которые могут добавить разработчики Cura в будущем.
*   `-> bool`: Явное указание, что функция возвращает булево значение (Успех/Провал).

## 2. Проблема генерации превью (`Snapshot returned None`)

### Симптомы
Файл сохраняется, но на экране принтера Snapmaker вместо картинки модели — пустота или стандартная иконка. В логах (если включить отладку) видно сообщение `Snapshot returned None`.

### Причина
Cura 5.x использует библиотеку Qt6 для отрисовки интерфейса. Процесс создания снимка экрана (`Snapshot.snapshot`) асинхронный и зависит от работы графического движка (OpenGL).
Когда плагин просит сделать снимок "мгновенно", движок часто не успевает отрисовать сцену или находится в заблокированном состоянии, возвращая `None` (пустоту).

### Решение: Механизм повторных попыток (Retry & Force Update)

Мы полностью переписали функцию `__generateThumbnail`, превратив её из простого запроса в настойчивого "папарацци".

#### Шаг 2.1. Импорт необходимых модулей
В начало файла добавлены модули для работы с системой, временем и управлением приложением Qt.

```python
import os
import time
from PyQt6.QtCore import QBuffer, QCoreApplication # QCoreApplication нужен для processEvents()
```

#### Шаг 2.2. Принудительное обновление сцены
Перед съемкой мы "дергаем" сцену, чтобы убедиться, что она инициализирована.

```python
scene = Application.getInstance().getController().getScene()
```

#### Шаг 2.3. Цикл ожидания (The Retry Loop)
Вместо одной попытки мы делаем серию запросов.

```python
image = None
for attempt in range(20): # Делаем до 20 попыток
    QCoreApplication.processEvents() # <--- ГЛАВНОЕ: Приказываем Cura обновить интерфейс ПРЯМО СЕЙЧАС
    time.sleep(0.05) # Ждем 50 миллисекунд, давая время видеокарте
    
    # Пытаемся получить снимок 300x300 (стандарт Snapmaker)
    image = Snapshot.snapshot(300, 300)
    
    if image: # Если картинка получена — выходим из цикла победителем
        break
```
*   `QCoreApplication.processEvents()`: Это команда движку Qt обработать все накопившиеся события (клики, перерисовки). Без этого Cura может "зависнуть" внутри долгой операции сохранения и не обновить картинку.

#### Шаг 2.4. План Б (Fallback)
Иногда (редко) драйвер видеокарты не хочет отдавать текстуру определенного размера (например, не кратного 16 или 64). Если `300x300` не удалось получить за 20 попыток, мы пробуем размер поменьше.

```python
if not image:
     image = Snapshot.snapshot(200, 200) # Попытка №2 с меньшим разрешением
```

#### Шаг 2.5. Проверка на "пустышку"
Даже если объект `image` вернулся, он может быть невалидным (нулевого размера).

```python
if image.isNull():
     return "" # Возвращаем пустую строку, чтобы не сломать G-код мусором
```

## Итог
Благодаря этим изменениям плагин теперь "дожидается", пока Cura соизволит нарисовать модель, и корректно встраивает её в G-код в формате Base64, который понимает Snapmaker.
